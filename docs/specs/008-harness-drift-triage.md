**一句话**：把独立 latest 视为观察信息，以 Harness 宿主和完整依赖约束选择升级候选；只有实际兼容验证通过的组合才能更新基线。

## 1. 背景与问题

PR 13 已解决缺 gitHead 导致的来源发现失败。2026-11-05 重新实际验签和校验 tarball 后，harness-watch 仍返回 drift：15 个相关包的 latest 与当前 lockfile 不同。这些差异本身不证明当前插件运行失败。

实际证据：

- `@deepseek-ai/dsh` 默认渠道仍为当前基线 0.2.1-rc.5。
- cordis 当前 4.0.5、latest 4.1.0；schemastery 当前 3.18.5、latest 3.19.0。Harness rc.5 分别要求 `~4.0.5` / `~3.18.5`，这两个新 minor 超出了其声明范围。
- dsh-agent 当前 0.2.1-rc.5、latest 0.1.0-rc.6；dsh-tools 当前 0.2.1-rc.5、latest 0.0.1-rc.1；dsh-util-values 当前 0.2.1-rc.5、latest 0.1.2-alpha.2。其 next 指向 0.2.2-rc.1，但本任务不追 next/alpha 标签。
- 当前 CLI 仅用字符串不等判断漂移，discover 把独立 latest 收集成固定目标，缺少组合可满足性判断。

用户在本会话明确目标：在各种依赖包能兼容的前提下选择更新组合；某组件升级导致其他组件不能用，就不升级该组件。本 spec 因此修正目标选择，而非仅加入已接受告警清单。

## 2. 范围

1. 区分独立发布观察、依赖可满足的候选组合、完整验证过的支持基线。
2. 以默认渠道 Harness 宿主为发布锚点，根据其实际 dependency/peer 关系及插件必须保留的能力选择精确候选。
3. 让 discover、harness-watch 和 routine 消费同一组合判定，防止告警与实际安装目标分离。
4. 更新告警分类、证据输出、回归测试和维护文档。

## 3. 非目标

不要求所有包达到各自 latest；不自动降级当前正常组件；不追 next/alpha 标签或任意未来发布；不删除公共能力来兼容新组件；不将 peer 约束可满足称为实测兼容。不改变插件 I1–I10、五工具、六个发布 skill、asc pin、自动合并权限或主副本同步权限。不通过 force/legacy-peer-deps 绕过依赖冲突，不自动删除 issue。

## 4. 契约变更

| 面 | 变更 |
|---|---|
| 独立 latest | 保留每个包的精确观察记录，附落后/超出约束等原因，不直接成为必须安装的目标 |
| Harness 目标 | 选择有实际宿主依赖证据且依赖约束可满足的精确组合；独立包仍可更新，不假设同版本号 |
| 状态 | 明确 observation / candidate / verified；候选并不等于支持基线 |
| harness-watch | 按兼容候选相对基线的变化和验证状态告警，独立 latest 的不适用差异保留为信息 |
| 来源和恢复 | 延续 spec 007 的实际验签、摘要、固定版本再验证及 v3 key；固定目标不被运行中的新 latest 替换 |
| 版本支持 | 新宿主支持范围可在适配 spec 中调整；不能靠永久沿用旧宿主范围屏蔽新宿主发布 |

这是维护目标选择与告警判定的契约变更。用户随后明确要求“按照这个原则，先调整一下当前整个 plugin 的依赖版本，锁定在经过验证、能一起工作的最新组合，然后更新自动更新的原则”，授权本方案的依赖核验、实施与自动维护规则同步；不再重复确认。原始差异不得偷偷改成“没有发布变化”。

实现采用 npm 原生 strict-peer-deps 解析宿主精确版本：在新建临时目录使用隔离配置/cache，package-lock-only、ignore-scripts、无 force/legacy-peer-deps，不安装或运行包代码。解析包含完整 transitive/peer 依赖，相关共享组件必须唯一且可从顶层解析；产物身份再与官方精确 manifest/签名/字节核对。discover/harness-watch 因解析新增临时本地写，退出时仅清理本次创建的临时目录，不修改 checkout、用户配置或全局工具；文档与 routine 必须明确此副作用。零新增运行时依赖。

## 5. 行为规格

### 5.1 发现与候选选择

1. 查询 dsh 的 latest，固定该精确宿主发布及其实际依赖声明。latest 本身为 rc 时允许；不查询 next/alpha 标签。宿主较基线回退必须显式报告，不自动降级。
2. 保留所有相关独立包的 latest 观察，逐一验证官方 npm 来源、有效签名及真实 tarball SHA-512。观察失败不能解释为无更新。
3. 在宿主实际 dependency/peer 图和插件需保留的能力约束下解析候选；不简单强制所有包同号，也不直接拼接独立 latest。直接/间接包的要求都必须考虑，单独检查宿主顶层字段不够。
4. 若兼容范围中存在多个版本，优先选择范围内更新的版本，并保留精确选择和依赖证据。仅因版本数字更高且未被默认渠道发布线支持的 prerelease，不自动成为升级目标；解析不能用强制安装忽略冲突。实现不得新增运行时依赖。
5. 当前宿主下独立包可有新候选；新宿主发布则重新解算新组合并评估插件声明的适配需求。当前 package.json 的旧范围不能成为永远拒绝新宿主的借口。
6. 独立 latest 低于当前已验证基线不触发自动降级；高于宿主或其他组件允许范围时记录暂缓原因。具体不适用结论需有对应精确版本和实际约束证据，不能仅靠包名前缀或历史豁免。
7. 无法取得完整关系或发现冲突时返回 blocked/unknown 和证据，不能假装已找到兼容目标。不能证明安全组合时保留当前已验证基线。

### 5.2 验证与基线推进

1. 候选先生成隔离安装计划和锁文件，再逐项验证固定产物和实际安装锁身份。来源校验、签名、摘要或锁文件不一致继续阻塞。
2. 在独立 worktree 安装并进行适配；保留真实 Harness、Node22/24、完整 npm run verify、旧基线支持验证等现有门禁。
3. 某组件升级引起不可解决的依赖冲突或功能回归，不推进该组件基线；报告失败候选和原因。先判断能否在既有公共契约内适配，不能删除功能、弱化测试或修改权限来通过。
4. 失败候选不得标 verified，也不得被“已评估”记录覆盖成成功。相同固定目标的重复尝试遵守既有恢复、去重与最多三轮修复规则，不借自动回退重置预算或另开重复 PR。
5. 只有目标来源、安装一致性、完整本地验证及 PR 所需 CI 通过，才可在人工合并后推进仓库支持基线；AUTO_TO_PR 不执行自动合并、主副本同步或发布。

### 5.3 告警语义与 issue 收口

1. 当前宿主组合已验证，且未发现适用的新候选时，独立旧标签和超出组合约束的版本作为 `observations` 信息输出，不导致“当前组合故障”的误导性告警。必须公开选择结果、观察差异和暂缓原因。
2. 发现适用的新候选而基线尚未验证/推进时，保留 actionable drift；依赖矛盾、来源失败、未知图和实际兼容测试失败继续以非零退出告警。不得加入通配符、永久忽略、任意环境变量屏蔽或把 unknown 转为成功。
3. 未验证候选不能被称为兼容版本。对“宿主约束明确不允许的独立发布”与“已选候选的真实冲突”分别报告，不混为一个成功状态。
4. 独立包、宿主、约束、产物身份或基线改变时重新判断，不依赖过期本地确认缓存。固定目标仍保留 v3 身份和版本组合 key，不伪造同步状态。
5. issue 12 收口条件：实现及本次逐项诊断证据合入 main，在该 main 上实际运行 upstream-watch；发现失败已解决，剩余差异均有约束依据且无未处理的适用候选、unknown 或失败验证。若仍有待适配候选，继续保留 issue 并说明剩余工作。关闭动作按用户授权执行，保留历史。

## 6. 安全与审批影响

I1–I10 无变化；所有来源校验和安装前验证保留。只调整开发维护的目标选择和告警语义，不能授权真实 ASC 写、发布或自动合并。用户已明确要求依此调整依赖及自动维护规则，本次按该授权实施；合并、发布和主副本同步仍不在自动执行范围。

## 7. 兼容与迁移

spec 005/007 的独立发布观察能力保留，独立 latest 不再直接代表安装组合。v3 产物身份及 key 算法继续使用；若新增候选元数据，必须明确字段校验与历史读取路径，不将旧 JSON 当作兼容认证。部署 routine 必须与代码同步，main 尚无实现时不能仅靠 prompt 宣称已部署。

## 12. 实施记录

用户明确要求后进入实施。当前组合实际版本无需升降；package.json 与锁文件的宿主 engines.dsh 精确为 0.2.1-rc.5，Cordis/Schemastery peer 从 tilde 收紧为已验证 4.0.5/3.18.5，其余相关 dsh-* peer/dev 本已精确为 rc.5。未来新组合验证后同步推进这些 pin；收窄宿主及 peer 要求属于本次兼容性变更，README/CONTRACT 同步。

验证结果（2026-11-05）：

- 新增兼容回归初次 12 项中 11 项失败，复现独立 latest 混装/降级及缺少组合解析。评审又复现安装锁嵌套共享实例未检查、产品 peer 与开发锁不一致两项，均先红后绿；最终新增 17 项高信号回归。
- 官方发布关系逐项核对确认：当前默认宿主图中的 15 个相关包仍是上述组合。真实隔离 npm 严格解析及实际产物验签/摘要后，harness-watch 返回 unchanged，changes=[]，15 项独立发布差异保留 observations。
- 固定宿主和所选组件再次解析，连同实际插件安装锁的包集/身份/共享实例复验：16 个产物 verified，validation 明确为 artifacts-and-dependency-resolution-only。首次冷缓存解析 120 秒超时后改为有界 5 分钟、显式 IPv4 优先；未关闭 strict-peer-deps 或通过 force 绕过。
- npm ci --ignore-scripts --strict-peer-deps --no-audit --no-fund 成功，按锁安装 92 个包；无包版本升降或下载脚本执行。
- 最终 npm run verify 全部八阶段通过：20 suites / 387 tests，typecheck、clean build、pack-manifest、contract-combos，以及 asc 6.3.0 的 28 条命令契约、1,932 条分类路径、真实 Harness subprocess 离线 smoke 6 次调用。Node 本地 24.14.0；PR Node22/24 CI 另行确认。workflow YAML 语法校验通过。
